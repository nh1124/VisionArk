# Ruler Nodeの役割とファイル管理に関する報告書

## 1. Ruler Nodeの現在の役割
Ruler Nodeは、VisionArkシステムにおいて**「組織化（Organizer）」**と**「統治（Governance）」**を担うメンバーノードです。

### 主な役割
- **ファイル組織化と索引作成 (File Organization & Indexing)**:
  - プロジェクト内のファイルが適切なディレクトリに配置されているか監視し、必要に応じて移動・整理します。
  - `REF.md` やディレクトリリストを維持し、他のノードが情報を検索しやすくします。
  - 不要になった古いファイルのアーカイブやクリーンアップを行います。
- **タスク管理とスケジューリング (Task Management & Scheduling)**:
  - Life Balance System (LBS) と連携し、ユーザーの負荷（Fatigue）が限界を超えないようスケジュールを調整します。
  - プロジェクトのタスクリストを定期的に刷新（Pruning）し、実行可能な状態に保ちます。

### 備えているツール
- `save_artifact` / `delete_artifact`: ファイルの保存と削除。
- `list_files` / `read_reference`: ファイルの閲覧。
- `get_lbs_schedule` / `get_load_on_day`: ユーザーのスケジュールと負荷の把握。
- `create_task` / `update_task`: タスクの実行管理。

---

## 2. 現在のAgentによるファイル管理方法
現在のエージェント（各ノード）によるファイル管理は、主に `save_artifact` ツールを介して行われていますが、以下の特徴と課題があります。

### 現状のプロセス
- **分散された生成**: 各ノード（Researcher, Planner等）が個別に `docs/` や `artifacts/` 内にファイルを生成します。
- **緩やかな構造**: 生成されるパスやファイル名は各ノードの判断に委ねられており、システムレベルでの厳格なバリデーションはありません。
- **手動の索引更新**: 現在、「ディレクトリリストの更新」はRuler Nodeの責任としてプロンプトに記載されていますが、ファイル生成時に自動で索引が更新される仕組み（トリガー）は実装されていません。

### 課題
- ファイルが増加するにつれ、どのファイルが最新で、どのファイルが参照用なのかが不明確になりやすい。
- 旧バージョンの計画書や一時的な調査レポートが整理されずに蓄積される。

---

## 3. 規則正しいファイル生成・管理のための手法（提案）
VisionArkがより自律的かつ整理された状態を保つため、以下の手法を提案します。

### A. 標準ディレクトリ構造の定義
`docs/` 以下に目的別のサブディレクトリを定義し、エージェントがこれに従うようプロンプトまたはツールで制約を設けます。
- `docs/plans/`: 承認待ち、または実行中の実装プラン。
- `docs/reports/`: 調査結果、分析レポート。
- `docs/specs/`: 機能の仕様、システムデザイン。
- `docs/audits/`: コードレビューやセキュリティ監査の結果。
- `docs/archive/`: 古くなったファイル。

### B. ファイル命名規則の統一
`snake_case` を基本とし、以下のプレフィックスを付与することで時系列やカテゴリを明確にします。
- `[YYYYMMDD]_[Category]_[Title].md`
- 例: `20260129_report_ruler_node_investigation.md`

### C. 標準ヘッダー（メタデータ）の導入
すべての生成ファイルに、以下のようなメタデータセクションを必須とし、自動処理のトリガーとします。
```markdown
---
title: タイトル
date: 2026-01-29
author: [Node Name]
status: active | draft | completed | obsolete
related_tasks: [Task ID]
---
```

### D. Rulerによるインデックス管理（カタログ化）
- **Registryシステム & Watcher連携**:
  - `FileService` の **Watcher機能** を利用し、`docs/` 以下にファイルが保存された際、自動的に Ruler Node に「インデックス更新タスク」を割り当てます。
  - Ruler Node はこのタスクを受け取り、`docs/INDEX.md` を解析・更新して、新しいファイルの概要とリンクを追記します。
- **ライフサイクル管理**:
  - Ruler Node が定期的に（例：毎日深夜のAESタスクとして）実行され、`status: completed` かつ一定期間経過したファイルを `archive/` に自動移動します。

### E. 知識ベース（Knowledge Core）への自動登録
保存されたファイルの内容を自動的にベクトル化し、RAG（検索拡張生成）のソースとして `MemoryNode` が常時利用可能な状態にします。これにより、ファイル名が不明でも「最近のスキルマイニングの報告」などの自然言語でファイルを特定可能になります。
