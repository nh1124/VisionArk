# Agent Skill Investigation Report

## 1. Agent Skill とは何か

### 概要
"Agent Skill"（エージェントスキル）とは、AIエージェントに特定のドメイン知識やタスク遂行能力を付与するための再利用可能なパッケージです。
従来の「ツール（Tools）」が「エージェントが実行できるアクション（関数やAPIコール）」を指すのに対し、スキルは「そのツールをいつ、どのように使うか」という**専門知識（Know-how）と手順（Workflow）**を含みます。

### Tools vs Skills
| 特徴 | Tools (道具) | Skills (技術/技能) |
| :--- | :--- | :--- |
| **役割** | 実行能力（What to do） | 遂行能力（How to do） |
| **構成要素** | 関数、API、検索機能など | ツール + プロンプト（指示書） + ドキュメント |
| **主体** | 受動的（呼ばれたら動く） | 能够的（目的達成のためにツールを組み合わせる） |
| **例** | `calculator.add()`, `web_search.search()` | 「財務分析スキル」（計算機と検索を使ってレポートを書く手順） |

### 最近のトレンド
- **Model Context Protocol (MCP)**: AIモデルと外部データ・ツールを接続する標準プロトコル。スキルはこのMCP上で提供されるリソースとして実装される傾向にあります。
- **Agentic Workflow**: 単発のツール実行ではなく、複数のステップを経て目標を達成するワークフロー全体を「スキル」として定義し、共有・再利用する動きが活発です。
- **File-System Based**: スキルを `SKILL.md` のようなファイルとして定義し、読み込ませるだけでエージェントがその能力を獲得する仕組みが一般的になりつつあります。

## 2. VisionArkへの導入・強化案

現状のVisionArkは `BaseTool` を継承したクラス（例: `SendLineMessageTool`）として「ツール」を実装していますが、これらを効果的に組み合わせる「スキル」の概念はまだ明示的に存在しません（`Node` のプロンプトに依存しています）。

### 導入コンセプト
**"Pluggable Intelligence"（プラグ可能な知能）**
ファイルシステム上にスキル定義を配置するだけで、VisionArk上の任意のエージェント（Node）がそのスキルを習得できる仕組みを導入します。

### 技術的実装案

#### A. ディレクトリ構造
`core/backend/skills/` ディレクトリを新設し、スキルごとにサブディレクトリを切ります。

```
core/backend/skills/
└── analyze_competitor/        # スキル名
    ├── SKILL.md               # スキル定義（メタデータ + 指示プロンプト）
    └── tools.py               # このスキル専用のツール（オプション）
```

#### B. `SKILL.md` フォーマット案
YAML Frontmatterでメタデータを定義し、本文でエージェントへの指示（システムプロンプトの一部となる）を記述します。

```markdown
---
name: analyze_competitor
description: 競合他社のWebサイトを分析し、強みと弱みをレポートするスキル
tools:
  - search_web
  - read_url_content
---
# 競合分析手順
1. 指定された競合の社名を検索し、公式サイトを特定する。
2. 公式サイトの "About Us", "Services" ページを読み込む。
3. 以下の観点で分析を行う:
   - ターゲット顧客
   - 提供価値
   - 価格帯
...
```

#### C. システム変更点
1.  **Skill Registry (`va_sdk/skill_registry.py`)**:
    *   起動時に `skills/` ディレクトリをスキャンし、`SKILL.md` をロードする機能を実装。
2.  **Node Model Update**:
    *   `Node` テーブルに `skills` カラム（JSON list）を追加（または既存の `meta_payload` を活用）。
3.  **Prompt Injection**:
    *   エージェント起動時（`NodeFactory`）、指定されたスキルの `SKILL.md` の内容をシステムプロンプトに動的に注入（Inject）するロジックを追加。

### 期待される効果
*   **プロンプト管理の効率化**: 巨大なシステムプロンプトを「スキル」単位に分割して管理できる。
*   **再利用性**: 「Web調査スキル」「コードレビュー能力」などを複数のプロジェクト/エージェントで共有可能になる。
*   **拡張性**: 新しい能力を追加する際、Pythonコードを書かずにMarkdownだけで完結するケースが増える（既存ツールを組み合わせる場合）。

## 3. 動的スキル獲得と管理の高度化案 (Refined)

ユーザーからのフィードバックに基づき、スキルの動的学習と管理UIについて追加検討しました。

### A. 動的スキル獲得 (Dynamic Acquisition)
「ユーザーのやり方を学習してスキルにする」ための2つのアプローチと、その統合案です。

| 手法 | 1. バックグラウンド分析 (Queue) | 2. Knowledge Core拡張 (Time-series) |
| :--- | :--- | :--- |
| **仕組み** | 定期的に過去のタスクログを分析し、反復されるパターンを抽出・構造化して `SKILL.md` の候補を作成する。 | ユーザーの行動履歴・文脈をベクトル化して蓄積し、類似状況下で「過去の成功手順」としてRAG的に提示する。 |
| **性質** | **「蒸留 (Distillation)」** <br> 暗黙知を形式知（ファイル）に変換する。 | **「想起 (Recall)」** <br> 文脈に応じた直感的な行動再生。 |
| **メリット** | 人間がレビュー・編集しやすい形で出力される。<br>システムの動作が明確・決定論的になる。 | リアルタイム性が高い。<br>明示的な定義が不要で、すぐに「なんとなく」使い始められる。 |
| **デメリット** | フィードバックループが遅い（バッチ処理）。<br>質の低いスキルが乱立するリスクがある。 | 文脈依存が強く、汎用的な「スキル」として他者と共有しにくい。<br>「なぜそう動いたか」の説明性が低い。 |

**推奨: ハイブリッドアプローチ**
1.  **短期記憶 (Knowledge Core)**: 日々の操作はKnowledge Coreが記憶し、類似状況で「前回こうしましたよね？」と提案・補完する（即時適応）。
2.  **長期記憶化 (Auto-Crystallization)**: 一定回数繰り返されたパターンや、ユーザーが高評価したフローをバックグラウンドで分析し、**「スキル候補 (Draft Skill)」** として生成・提案する。
3.  **正式化**: ユーザーがそれを承認・編集することで、確定的な `SKILL.md`（静的スキル）としてシステムに登録される。

### B. 管理UIの必要性
マルチユーザー環境を前提とする場合、管理UIは**「必須」**と考えます。

*   **理由**:
    *   **パーソナライゼーション**: 開発者Aには「詳細な技術レビュー」スキルが必要だが、PMのBには「概要要約」スキルが必要など、役割によるスキルの取捨選択が必要。
    *   **コンフリクト回避**: 自動学習されたスキルが、意図せず他人の作業フローに干渉するのを防ぐ（デフォルトはPrivate設定など）。
    *   **透明性**: AIが「なぜその手順を選んだか」を確認し、修正するためのインターフェースが必要。

*   **ページ構成案 (Projects > Settings > Agent Skills)**:
    1.  **My Skills**: 自分専用のスキル（学習中のドラフト含む）。
    2.  **Team Skills**: チームで共有された安定版スキル。
    3.  **Marketplace (将来構想)**: システム標準や他チームのスキルを探す場所。
    4.  **Editor**: `SKILL.md` をGUIで編集・テストする画面。

### C. 静的 vs 動的のバランス
**「動的学習で提案し、静的に固定する」サイクル**を提案します。

- **静的設定 (Static)**:
    - **Core Skills**: システム動作に不可欠な基本能力（検索、ファイル操作など）。これらは手動で定義し、勝手に変更されないように保護する。
    - **Verified Skills**: チームで合意された標準プロセス。
- **動的学習 (Dynamic)**:
    - **Adaptive Layer**: ユーザーの癖や一時的なプロジェクトルール。Knowledge Coreによる「振る舞いの調整」レベル。
    - **Skill Mining**: 動的層から有用なものを「静的スキル」へと昇格させるプロセス。

**結論**: 最初から「すべて動的」にするのではなく、まずは**「静的スキル基盤」**を作り、その上に**「Knowledge Coreによる行動ログの蓄積と、そこからのスキル抽出（Mining）」**をアドオンで実装するのが現実的かつ効果的です。
