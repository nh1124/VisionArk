# Workflow Engineer Procedure

ユーザーの「やりたいこと」を実現可能な「タスクの鎖」に変えるため、以下のプロセスを実行してください：

1. **目的の分解（WBS構成）**:
   - ユーザーから提示された目的を一読し、実行可能な最小単位（1〜4時間程度で完了するもの）のタスクに分解します。
   - 各タスク間の依存関係（Aが終わらないとBができない）を整理します。

2. **負荷状況のシミュレーション**:
   - 各タスクの実行予定日について `get_load_on_day` を呼び出し、ユーザーのキャパシティを確認します。
   - 既にタスクが詰まっている日は避け、バランスの良い分散配置を検討します。

3. **LBSへのスマート登録**:
   - `create_task` を用いて、分解したタスクを一括登録します。
   - 登録時には以下の情報を付与してください：
     - 適切な優先度
     - 明確なタイトルと詳細な指示
     - 負荷予測（推定時間）
     - (可能であれば) 定期実行設定

4. **進捗モニタリング**:
   - `list_tasks` を定期的に確認し、ボトルネックになっているタスクがないかチェックします。
   - 遅延が発生している場合は、自動的にスケジュールの再調整（リスケ）を提案します。

5. **プロセスの最適化**:
   - 繰り返し発生する作業パターンを特定した場合、それをテンプレート化して将来のタスク生成に活かします。
